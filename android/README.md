# Pichome Android

一个轻量的 Android WebView 客户端，加载现有 Pichome 手机网页：

`https://pichome.lempet.top:5575/`

## 第一版功能

- 独立 APK、应用名称和图标
- 保持网页登录与 Cookie
- 支持网页选择并上传多个文件
- 支持网页视频播放及播放器全屏
- 支持 Android 返回键网页后退
- APK 专属请求自动通过 Caddy 入口认证，不显示账号密码框
- 为手机状态栏、导航栏和屏幕开孔预留系统安全区域，上下系统栏统一使用 `#303135` 深灰背景
- 左侧分类树使用 Element Plus 原生节点点击切换：点击文件夹名称展开直接子文件夹，再次点击收起
- APK 隐藏左右侧栏箭头按钮，支持边缘滑入打开、在侧栏内反向滑动收回，并让侧栏实时跟随手指
- APK 保留顶部时间/电量状态栏，将底部导航栏设为可临时唤出的沉浸式状态，并向系统申请左右整条物理屏幕边缘作为侧栏手势区
- 图片和视频详情使用贴满手机屏幕左右边缘、按素材比例计算高度的居中弹窗，点击外部关闭
- 图片和视频详情顶部提供不依赖图标字体的水平镜像预览图标按钮，位于“设置为封面图”左侧；按钮只改变当前预览且再次点击恢复，切换素材时自动重置，视频进入原生全屏及逐帧缓存画面时继续保持一致的镜像方向
- 视频详情打开后自动播放；普通预览中视频内部的 XGPlayer/原生播放控件始终隐藏，图标式播放/暂停、静音/恢复声音、倍速循环、原生全屏四个按钮独立放在总时间进度条上方，并实时同步视频状态；全屏按钮直接请求当前视频元素进入 Android 原生视频全屏层，进入前会提交当前逐帧位置并完整退出逐帧隐藏状态，保证即使做过逐帧预览，点击全屏画面也能持续唤出播放、暂停、最小化等原生控制；全屏自动切换到传感器横屏，退出后恢复进入前的屏幕方向与普通预览控件状态；逐帧滑动区上方提供横向贴满手机屏幕、带当前时间/总时长的视频总进度滑块，可直接拖到任意时间且松手后没有惯性，控制栏和滑块均作为悬浮控件显示而不压缩视频窗口；逐帧滑动区按下即进入逐帧，从按下位置开始每移动 7dp 预览一帧，向右前进、向左后退、按住可反复改变方向，松手会立即丢弃尚未呈现的移动距离，不再继续滚动；服务端按视频版本懒生成每秒一张 WebP 帧图集，App 将图集纳入可清理、可限额的持久素材缓存，并在内存中只保留当前位置前后 7 秒、最多并发读取 2 段的环形窗口，因此同一范围内前进和后退都直接按绝对帧取图；手指快速跨段时会淘汰旧排队任务，不产生松手后的惯性滚帧；正常播放期间原有约 96 帧的低分辨率环形画面缓存和精确 seek 继续作为图集尚未就绪或生成失败时的兼容回退；视频前 1 秒的回退路径仍直接显示原视频高清帧，避免开头画面被低分辨率缓存放大后模糊；屏幕底部仍提供 144×96px 的后退一帧、前进一帧按钮，短按走一帧，长按以 1× 速度连续前进或反向预览
- APK 双击素材时只把被点击卡片的 `dpath` 传入详情页并将索引固定为 0，不再预载相邻素材；自动播放仅作用于中央当前视频
- APK 内图片和视频详情页按媒体比例及剩余屏幕高度自适应显示
- 外部域名交给系统浏览器打开
- 不申请存储权限；APK 内隐藏下载按钮并拦截下载请求
- 图片、视频和逐帧 WebP 图集使用同一套 App 私有磁盘自动缓存：图片边显示边缓存，视频分段播放时后台补全，图集按秒、按媒体版本持久保存；打开头像用户菜单并点击“查看缓存”，可查看缓存用量和文件数、清理缓存，并把容量上限设为 512MB/1GB/2GB/4GB/8GB/16GB；默认 4GB、单文件上限 512MB，空间不足时按最久未使用自动清理，不申请外部存储权限

## 构建

```bash
cd /home/wangjiafeng/pichome/android
./build-apk.sh
```

调试 APK 输出位置：

`app/build/outputs/apk/debug/app-debug.apk`

## 安装

连接开启 USB 调试的 Android 手机后：

```bash
/home/wangjiafeng/构建apk依赖包/android-sdk/platform-tools/adb install -r app/build/outputs/apk/debug/app-debug.apk
```

当前是调试签名版本，适合直接安装测试。正式长期使用时可以再创建独立签名的 release APK。
